Introduction to Networks (บทนำสู่ระบบเครือข่าย)

🌐 โครงสร้างพื้นฐานของระบบเครือข่าย (Network Fundamentals)

ระบบเครือข่ายคอมพิวเตอร์ (Computer Network) คือการนำอุปกรณ์ตั้งแต่ 2 เครื่องขึ้นไปมาเชื่อมต่อกันเพื่อแลกเปลี่ยนข้อมูลและแบ่งปันทรัพยากร โดยมีองค์ประกอบหลักได้แก่ อุปกรณ์ปลายทาง (End Devices เช่น PC, Server, Smart Phone), อุปกรณ์ตัวกลาง (Intermediary Devices เช่น Switch, Router, Firewall) และตัวกลางส่งสัญญาณ (Network Media เช่น UTP Cable, Fiber Optic, Radio Frequencies)

LAN (Local Area Network)

เครือข่ายครอบคลุมพื้นที่จำกัด เช่น ภายในห้อง, อาคารสำนักงาน หรือบ้าน

MAN (Metropolitan Area Network)

เครือข่ายครอบคลุมระดับเมืองหรือชุมชน เชื่อมต่อหลาย LAN เข้าด้วยกัน

WAN (Wide Area Network)

เครือข่ายระยะไกลระดับประเทศหรือทั่วโลก เช่น ระบบอินเทอร์เน็ต

🏢 สถาปัตยกรรม Campus Network แบบ 3 ระดับ (Hierarchical Design)

การออกแบบโครงสร้างเครือข่ายองค์กรที่ดีตามมาตรฐาน Cisco มักใช้โมเดลลำดับชั้น (Three-Tier Hierarchical Model) เพื่อให้ง่ายต่อการขยายตัว (Scalability), ปลอดภัย (Security) และง่ายต่อการแก้ไขปัญหา (Maintainability):

Layer (ระดับ) บทบาทหน้าที่หลัก อุปกรณ์ที่ใช้งาน
Core Layer ทางด่วนความเร็วสูง (High-Speed Backbone) มุ่งเน้นการส่งผ่านข้อมูลปริมาณมากอย่างรวดเร็วที่สุด มีความเสถียรภาพสูงและไม่ทำ Packet Filtering ที่ซับซ้อน High-end Core Switches, Optical Routers
Distribution Layer ชั้นนโยบายและควบคุม (Policy-based Connectivity) ทำหน้าที่กำหนดขอบเขต Routing, กรองความปลอดภัยด้วย ACL, บังคับใช้ QoS และเชื่อมโยงระหว่าง Access กับ Core Layer 3 Distribution Switches, Routers
Access Layer จุดเชื่อมต่ออุปกรณ์ของผู้ใช้งาน (Workstations, IP Phones, Wireless AP, Printers) ควบคุมการเข้าถึงพอร์ต (Port Security, 802.1X) และกำหนดค่า VLAN Layer 2 Access Switches, Access Points

Networking Devices & Switching Concepts

🔍 Collision Domain vs Broadcast Domain

Collision Domain (ขอบเขตการชนกันของสัญญาณ)

พื้นที่ที่สัญญาณไฟฟ้าอาจเกิดการชนกันเมื่อส่งพร้อมกัน:
• Hub: ทุกพอร์ตอยู่รวมใน Collision Domain เดียวกัน
• Switch: แยก 1 พอร์ต = 1 Collision Domain (ทํางานแบบ Full Duplex จึงไม่ชนกัน)

Broadcast Domain (ขอบเขตการแพร่กระจายสัญญาณ)

พื้นที่ที่เมื่อส่ง Broadcast Frame (MAC: FF:FF:FF:FF:FF:FF) ทุกเครื่องจะได้รับ:
• Switch: ทุกพอร์ตอยู่ Broadcast Domain เดียวกัน (ยกเว้นแบ่ง VLAN)
• Router: เป็นอุปกรณ์ที่ ตัดแบ่งขอบเขต Broadcast Domain (1 Interface = 1 Broadcast Domain)

กลไกการทำงานของ Switch (CAM / MAC Address Table)

  1. Learning: ตรวจสอบ Source MAC Address ของเฟรมที่เข้ามายังพอร์ต แล้วบันทึกลง MAC Table คู่กับหมายเลขพอร์ต
  2. Flooding: หาก Destination MAC Address ยังไม่ปรากฏในตาราง (Unknown Unicast) Switch จะส่งเฟรมออกไปทุกพอร์ต (ยกเว้นพอร์ตที่รับเข้ามา)
  3. Forwarding / Filtering: หาก Destination MAC มีบันทึกในตารางแล้ว Switch จะส่งเฉพาะออกพอร์ตปลายทางนั้นพอร์ตเดียว
  4. Aging: ลบ Entry ที่ไม่มีการติดต่อสื่อสารเกินเวลา Aging Timer (ค่าเริ่มต้น 300 วินาที)

IPv4 Address & Classes (โครงสร้างที่อยู่ IPv4)

🔢 โครงสร้าง IPv4 และการแบ่งคลาส

IPv4 Address มีขนาด 32 bits แบ่งออกเป็น 4 ชุด (Octets) ชุดละ 8 bits คั่นด้วยเครื่องหมายจุด ประกอบด้วยส่วน Network ID (ระบุเครือข่าย) และ Host ID (ระบุเครื่องลูกข่าย):

Class ช่วง IP (First Octet) Default Mask สัดส่วน Net:Host จำนวน Hosts / Net การใช้งาน
Class A 1.0.0.0 - 126.255.255.255 255.0.0.0 (/8) N.H.H.H 16,777,214 องค์กรขนาดใหญ่มาก
Class B 128.0.0.0 - 191.255.255.255 255.255.0.0 (/16) N.N.H.H 65,534 องค์กรขนาดกลาง-ใหญ่
Class C 192.0.0.0 - 223.255.255.255 255.255.255.0 (/24) N.N.N.H 254 องค์กรขนาดเล็ก / ทั่วไป
Class D 224.0.0.0 - 239.255.255.255 - - - Multicast Groups
Class E 240.0.0.0 - 255.255.255.255 - - - วิจัยและทดลอง (Experimental)
ช่วง Private IP Address (RFC 1918) ที่ห้ามวิ่งบนอินเทอร์เน็ตสาธารณะ:
• Class A: 10.0.0.0 - 10.255.255.255 (/8)
• Class B: 172.16.0.0 - 172.31.255.255 (/12)
• Class C: 192.168.0.0 - 192.168.255.255 (/16)

Subnetting & VLSM (การคำนวณแบ่งเครือข่ายย่อย)

📐 สูตรคำนวณ Subnetting ด้วยเทคนิค "Magic Number"

การทำ Subnetting คือการยืมบิตจากส่วน Host ID มาเพิ่มให้ส่วน Network ID เพื่อสร้างวงเครือข่ายย่อย:

  • จำนวน Subnets ที่ได้: $2^n$ (โดย $n$ คือจำนวนบิตที่ยืมมา)
  • จำนวน Hosts ทั้งหมดต่อ Subnet: $2^h$ (โดย $h$ คือจำนวนบิต Host ที่เหลืออยู่)
  • จำนวน Usable Hosts: $2^h - 2$ (หัก Network ID ตัวแรก และ Broadcast ID ตัวสุดท้ายออก)
  • Magic Number (ขนาดช่วงก้าว): $256 - \text{Subnet Mask Octet ที่ถูกยืม}$
ตัวอย่าง: ต้องการแบ่ง Network 192.168.1.0/24 ให้เป็น 4 Subnets
1. ต้องยืม 2 บิต ($2^2 = 4$) ทำให้ Prefix เปลี่ยนจาก /24 เป็น /26
2. Subnet Mask กลายเป็น 255.255.255.192
3. Magic Number = $256 - 192 = 64$
4. จะได้ 4 วง: 192.168.1.0/26, 192.168.1.64/26, 192.168.1.128/26, 192.168.1.192/26

Function of Routing (หลักการทำงานของ Router)

🧭 การค้นหาและตัดสินใจเลือกเส้นทาง (Path Determination)

Router ทำงานที่ Network Layer (Layer 3) ทำหน้าที่รับแพ็กเก็ต ตรวจสอบ Destination IP และค้นหาเส้นทางที่ดีที่สุดในตารางเส้นทาง (Routing Table) โดยมีหลักเกณฑ์สำคัญ 3 ประการ:

1. Longest Prefix Match

เกณฑ์สำคัญที่สุด! Router จะเลือกเส้นทางที่มีความเจาะจงสูงสุด (Prefix ยาวสุด) เสมอ เช่น /28 ชนะ /24

2. Administrative Distance

หากมีหลาย Protocol เสนอเส้นทางที่มี Prefix เท่ากัน จะเลือก Protocol ที่มีค่า AD ต่ำสุด (น่าเชื่อถือที่สุด)

3. Metric (ต้นทุนเส้นทาง)

ภายใน Protocol เดียวกัน จะเลือกเส้นทางที่มีค่า Metric ต่ำสุด เช่น OSPF เลือก Cost ต่ำสุด, RIP เลือก Hop Count น้อยสุด

ตารางเปรียบเทียบ Administrative Distance (AD)

ที่มาของเส้นทาง (Route Source) ค่า AD มาตรฐาน ระดับความน่าเชื่อถือ
Directly Connected0สูงสุด (เชื่อมต่อสายตรง)
Static Route1สูงมาก (ผู้ดูแลระบบกำหนดเอง)
EIGRP Internal90สูง
OSPF110มาตรฐานสากล
IS-IS115มาตรฐาน
RIP120ต่ำ
External EIGRP170ต่ำมาก

Static Routing (การกำหนดเส้นทางแบบคงที่)

📍 รูปแบบคำสั่ง Static Routing

Static Route เหมาะสำหรับเครือข่ายขนาดเล็ก หรือเครือข่ายแบบ Stub Network ที่มีทางออกสู่ภายนอกเพียงทางเดียว มีข้อดีคือปลอดภัย ไม่กิน Bandwidth จาก Routing Updates แต่มีข้อจำกัดคือต้องแก้ค่าด้วยตนเองหากมีลิงก์ขาด:

Cisco IOS - Static Routing Examples 
! 1. Standard Static Route (ระบุ Next-hop IP)
Router(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2

! 2. Default Route (Quad-Zero: ชี้ออกอินเทอร์เน็ตหรือ Gateway ปลายทาง)
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1

! 3. Floating Static Route (สร้างเส้นทางสำรองโดยกำหนดค่า AD สูงกว่าปกติ เช่น 10)
Router(config)# ip route 192.168.20.0 255.255.255.0 10.0.1.2 10
Day 3 • Module 7

STP Concepts and EtherChannel

🌳 Spanning Tree Protocol (STP 802.1D / 802.1w)

เมื่อเชื่อมต่อสายสัญญาณ Switch แบบคู่ขนาน (Redundant Links) เพื่อป้องกันสายขาด อาจเกิดปัญหา Layer 2 Loops ส่งผลให้เกิด Broadcast Storm, MAC Table Thrashing และ Multiple Frame Transmission โปรโตคอล STP จึงถูกพัฒนาขึ้นเพื่อบล็อกพอร์ตส่วนเกินในเชิงตรรกะ และจะเปิดอัตโนมัติเมื่อสายหลักขาด:

Root Bridge Election:

Switch ที่มีค่า Bridge ID (Bridge Priority + MAC Address) ต่ำที่สุด จะชนะและได้รับเลือกเป็น Root Bridge

STP Port Roles:

• Root Port (RP): พอร์ตบน Non-root Switch ที่ไปถึง Root Bridge ดีที่สุด
• Designated Port (DP): พอร์ตที่ส่งข้อมูลลงในแต่ละ Segment
• Blocking / Alternate: พอร์ตที่ถูกปิดไม่ให้ส่งผ่านข้อมูลเพื่อกัน Loop

🔗 EtherChannel (Link Aggregation)

การรวมพอร์ตสายแลนกายภาพตั้งแต่ 2 ถึง 8 เส้น ให้เสมือนเป็น Logical Link เดียว (Port-Channel) ช่วยเพิ่มแบนด์วิดท์และสร้างความซ้ำซ้อนโดยที่ STP ไม่บล็อกพอร์ต:

โปรโตคอล โหมดที่ต้องจับคู่ (Modes) ลักษณะ
LACP (IEEE 802.3ad) active + active หรือ active + passive มาตรฐานเปิด ใช้งานร่วมกับทุกยี่ห้อได้ แนะนำให้ใช้งาน
PAgP (Cisco) desirable + desirable หรือ desirable + auto Cisco Proprietary
Static (On) on + on บังคับรวมลิงก์โดยไม่ส่งแพ็กเก็ตเจรจา (เสี่ยงหากปลายทางตั้งค่าไม่ตรงกัน)
Cisco IOS - การตั้งค่า LACP EtherChannel 
Switch(config)# interface range GigabitEthernet 0/1 - 2
Switch(config-if-range)# channel-group 1 mode active
Switch(config-if-range)# exit
Switch(config)# interface port-channel 1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20,30

VLANs and Trunks (การแบ่งเครือข่ายเสมือน)

🏷️ พอร์ต Access vs พอร์ต Trunk (IEEE 802.1Q)

VLAN (Virtual Local Area Network) ช่วยแบ่ง Broadcast Domain บน Switch เดียวกันเพื่อความปลอดภัยและประสิทธิภาพ พอร์ตที่เชื่อมต่อไปยังเครื่องลูกข่ายจะเป็น Access Port (ไม่ติด Tag) ส่วนพอร์ตที่เชื่อมต่อระหว่าง Switch ด้วยกันจะเป็น Trunk Port ที่มีการแนบ Header IEEE 802.1Q (4 Bytes) ระบุเลข VLAN ID (1 - 4094):

Cisco IOS - ตัวอย่างการสร้าง VLAN & กำหนด Trunk (จากสไลด์หน้า 227) 
! สร้าง VLAN พร้อมตั้งชื่อ
Switch(config)# vlan 10
Switch(config-vlan)# name Faculty_Staff
Switch(config)# vlan 20
Switch(config-vlan)# name Students
Switch(config)# vlan 99
Switch(config-vlan)# name Native_Mgmt
Switch(config-vlan)# exit

Switch(config)# interface FastEthernet 0/1

Switch(config-if)# switchport trunk allowed vlan 10,20,99
Day 3 • Module 9

Routing Between VLANs (Inter-VLAN)

⚡ การเชื่อมโยงข้อมูลข้าม VLAN (Inter-VLAN Routing)

เนื่องจากอุปกรณ์ในคนละ VLAN ไม่สามารถสื่อสารกันโดยตรงที่ Layer 2 ได้ จึงต้องอาศัยอุปกรณ์ Layer 3 เข้ามาทำ Routing:

แบบ Router-on-a-Stick (ROAS)

ใช้สายแลน 1 เส้นระหว่าง Switch และ Router โดยแบ่งพอร์ต Router ออกเป็น Sub-interfaces ย่อยตาม VLAN:

Router(config)# interface Gi0/0.10
Router(config-subif)# encapsulation dot1q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config)# interface Gi0/0.20
Router(config-subif)# encapsulation dot1q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0
แบบ Layer 3 Switch (SVI)

ใช้ความสามารถ Routing ภายใน Switch (Hardware-based Asic) ทำงานได้รวดเร็วมาก โดยใช้ Switched Virtual Interface:

L3Switch(config)# ip routing
L3Switch(config)# interface vlan 10
L3Switch(config-if)# ip address 192.168.10.1 255.255.255.0
L3Switch(config)# interface vlan 20
L3Switch(config-if)# ip address 192.168.20.1 255.255.255.0

Dynamic Routing Protocol Concepts

🔄 พื้นฐาน Dynamic Routing

โปรโตคอลแบบ Dynamic Routing ช่วยให้เราท์เตอร์แลกเปลี่ยนข้อมูลตารางเส้นทางกันโดยอัตโนมัติ และปรับเปลี่ยนเส้นทางทันทีเมื่อเกิดเหตุลิงก์ขัดข้อง (Network Convergence):

ประเภท อัลกอริทึม & ลักษณะ โปรโตคอลตัวอย่าง
Distance Vector คำนวณตามระยะทาง (Distance) และทิศทาง (Vector) ส่งตารางเส้นทางเป็นระยะ (Routing by rumor) RIPv2, EIGRP
Link-State Router ทุกตัวใน Area รู้ภาพรวม Topology แผนที่เดียวกันทั้งหมดผ่าน LSA และใช้อัลกอริทึม Dijkstra SPF OSPF, IS-IS
Path-Vector ใช้ส่งข้อมูลข้าม Autonomous System (AS) ระดับผู้ให้บริการอินเทอร์เน็ต BGP (Border Gateway Protocol)

OSPF Single Area Configuration

📡 การตั้งค่า OSPFv2 Single Area (Area 0 Backbone)

OSPF เป็น Link-State Protocol ยอดนิยม มีค่า AD = 110 คำนวณ Metric จาก Bandwidth ($\text{Cost} = \frac{10^8}{\text{Bandwidth in bps}}$) โดยทุก Area ใน OSPF จะต้องเชื่อมต่อเข้ากับ Backbone Area (Area 0):

Cisco IOS - การตั้งค่า OSPF Single Area (จากสไลด์หน้า 257) 
! 1. เปิดใช้ OSPF Process ID 1
Router(config)# router ospf 1

! 2. กำหนด Router ID ด้วยตนเอง (แนะนำเพื่อป้องกันการเปลี่ยนอัตโนมัติ)
Router(config-router)# router-id 1.1.1.1

! 3. ประกาศ Network ที่ต้องการให้ OSPF ทำงาน โดยใช้ Wildcard Mask
Router(config-router)# network 192.168.10.0 0.0.0.255 area 0
Router(config-router)# network 10.0.0.0 0.0.0.3 area 0

! 4. ปิดการส่ง Hello Packet ออกพอร์ต LAN เพื่อประหยัด Bandwidth และเพิ่มความปลอดภัย
Router(config-router)# passive-interface GigabitEthernet0/0/0

! 5. กระจาย Default Route (หากเราท์เตอร์นี้เชื่อมต่ออินเทอร์เน็ต)
Router(config-router)# default-information originate
Router(config-router)# exit
Day 4 • Module 11

Layer 3 Redundancy (FHRP & HSRP)

🛡️ กลไกความซ้ำซ้อนของ Default Gateway (HSRP)

โดยทั่วไปเครื่องลูกข่ายจะตั้งค่า Default Gateway เป็น IP เดี่ยว ทำให้หาก Router ตัวนั้นเสีย ผู้ใช้จะออกสู่อินเทอร์เน็ตไม่ได้ โปรโตคอล First Hop Redundancy Protocol (FHRP) เช่น HSRP (Hot Standby Router Protocol) ของ Cisco จึงสร้าง Virtual IP และ Virtual MAC เสมือนร่วมกันระหว่าง 2 Router:

Active Router:

ทำหน้าที่ส่งผ่านข้อมูลจริง ตอบ ARP Reply ด้วย Virtual MAC และส่ง Hello Message (Multicast 224.0.0.2) ทุก 3 วินาที

Standby Router:

คอยเฝ้าฟัง Hello Message หาก Active ขาดหายไปเกิน Hold Time (10 วินาที) จะยกระดับตนเองขึ้นเป็น Active ทันที

Cisco IOS - การตั้งค่า HSRP Active & Standby (จากสไลด์หน้า 269) 
! บน Router 1 (กำหนดให้เป็น Active)
R1(config)# interface GigabitEthernet 0/0/0
R1(config-if)# ip address 192.168.1.2 255.255.255.0
R1(config-if)# standby 1 ip 192.168.1.1       ! ชี้ Virtual IP เป็น Gateway ที่เครื่อง Client ใช้งาน
R1(config-if)# standby 1 priority 110         ! เพิ่มค่า Priority ให้ชนะ (Default 100)
R1(config-if)# standby 1 preempt              ! อนุญาตให้แย่งตำแหน่งกลับเมื่อตนเองกลับมาออนไลน์

! บน Router 2 (ทำหน้าที่ Standby)
R2(config)# interface GigabitEthernet 0/0/0
R2(config-if)# ip address 192.168.1.3 255.255.255.0
R2(config-if)# standby 1 ip 192.168.1.1
R2(config-if)# standby 1 priority 90
R2(config-if)# standby 1 preempt
Day 4 • Module 12

ACL Concepts (Access Control Lists)

🔐 การควบคุมความปลอดภัยด้วย Access Control Lists

ACL คือชุดกฎในการคัดกรองแพ็กเก็ต (Packet Filtering) ทำงานโดยการตรวจสอบบรรทัดต่อบรรทัดจากบนลงล่าง (Top-to-Bottom) เมื่อแพ็กเก็ตตรงกับกฎข้อใดจะหยุดตรวจสอบทันที และมีกฎแฝงบรรทัดสุดท้ายคือ Implicit Deny Any:

ประเภท ACL หมายเลข Numbered สิ่งที่สามารถกรองได้ กฎการติดตั้งที่เหมาะสม (Placement Rule)
Standard ACL 1 - 99, 1300 - 1999 กรองเฉพาะ Source IP Address เท่านั้น ควรวางไว้ ใกล้ปลายทางที่สุด (Close to Destination) เพื่อไม่ให้เผลอบล็อกทราฟฟิกไปหาที่อื่น
Extended ACL 100 - 199, 2000 - 2699 กรองทั้ง Source IP, Destination IP, Protocol (TCP/UDP/ICMP), Port Number ควรวางไว้ ใกล้ต้นทางที่สุด (Close to Source) เพื่อตัดทิ้งตั้งแต่เนิ่นๆ ประหยัดแบนด์วิดท์เครือข่าย
Cisco IOS - ตัวอย่างการสร้าง ACL กรองทราฟฟิก & ป้องกัน VTY (จากสไลด์หน้า 290-301) 
! Extended ACL 101: ปฏิเสธ Telnet (23) และ SSH (22) จาก Subnet 172.16.3.0/24 แต่ยอมให้ผ่านอย่างอื่น
Router(config)# access-list 101 deny tcp 172.16.3.0 0.0.0.255 any eq 23
Router(config)# access-list 101 deny tcp 172.16.3.0 0.0.0.255 any eq 22
Router(config)# access-list 101 permit ip any any

! ผูก ACL เข้ากับ Interface ฝั่งขาเข้า (Inbound)
Router(config)# interface GigabitEthernet 0/0/0
Router(config-if)# ip access-group 101 in
Router(config-if)# exit

! การใช้ Standard ACL ป้องกันการรีโมตเข้ามาทาง Line VTY
Router(config)# access-list 10 permit host 192.168.1.100
Router(config)# line vty 0 15
Router(config-line)# access-class 10 in
Router(config-line)# transport input ssh
